Register addresses from the Inven\+Sense MPU-\/9250 register map (RM-\/\+MPU-\/9250\+A-\/00) and the AK8963 datasheet. Nothing here is part of the driver\textquotesingle{}s public API; include \doxylink{MPU9250__interface_8h}{MPU9250\+\_\+interface.\+h} instead.\hypertarget{MPU9250__private_8h_mpu_layout}{}\doxysubsection{\texorpdfstring{How the two chips fit together}{How the two chips fit together}}\label{MPU9250__private_8h_mpu_layout}
An MPU9250 is really {\itshape two} dies in one package:\+ the MPU6500 (accelerometer + gyroscope), which the STM32 talks to directly over SPI, and a separate AK8963 magnetometer, which hangs off the MPU6500\textquotesingle{}s own {\bfseries{internal I2C master}} and is not reachable over SPI at all.

So reading the compass is a two-\/step dance:\+ the driver programs the I2C master registers (\doxylink{group__hal__mpu9250_ga614db921c27f375c632960a7f34999a4}{I2\+C\+\_\+\+SLV0\+\_\+\+ADDR}, \doxylink{group__hal__mpu9250_ga0553d56ecccd0fc8008505e712a9b075}{I2\+C\+\_\+\+SLV0\+\_\+\+REG}, \doxylink{group__hal__mpu9250_gad6fb6553534b0b9e9715db3e5a04ebca}{I2\+C\+\_\+\+SLV0\+\_\+\+CTRL}) to tell the MPU6500 "{}go fetch these bytes from the AK8963 for me"{}, and the result then appears in the \doxylink{group__hal__mpu9250_gaa6580b929fcb8b3e29fe45b73180d2bd}{EXT\+\_\+\+SENS\+\_\+\+DATA\+\_\+00} block, which {\itshape is} readable over SPI.

\begin{DoxyNote}{Note}
Multi-\/byte sensor values are big-\/endian:\+ the {\ttfamily \+\_\+H} register holds the high byte and {\ttfamily \+\_\+L} the low byte, so a reading is {\ttfamily (H \texorpdfstring{$<$}{<}\texorpdfstring{$<$}{<} 8) \texorpdfstring{$\vert$}{|} L}. The AK8963 is the exception — it is little-\/endian, {\ttfamily \+\_\+L} first. 
\end{DoxyNote}
