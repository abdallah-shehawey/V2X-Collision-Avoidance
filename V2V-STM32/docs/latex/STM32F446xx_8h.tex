\doxysubsection{Detailed Description}
STM32\+F446\+RE register map:\+ peripheral base addresses, register layout structs, and the typed pointers the MCAL drivers write to. 

\begin{DoxyAuthor}{Author}
Abdallah Abdelmoemen Shehawey 
\end{DoxyAuthor}
This is the hand-\/written replacement for ST\textquotesingle{}s CMSIS device header — the project deliberately uses no vendor HAL/\+\+LL code, so this file is the single point where a C symbol is bound to a physical peripheral address.

Each peripheral is described in two steps:\+
\begin{DoxyEnumerate}
\item a {\ttfamily \texorpdfstring{$<$}{<}PERIPH\texorpdfstring{$>$}{>}\+\_\+\+BASEADDR} constant, taken from the memory map in RM0390;
\item a {\ttfamily \texorpdfstring{$<$}{<}PERIPH\texorpdfstring{$>$}{>}\+\_\+\+Reg\+Def\+\_\+t} struct whose members are laid out in register order, so member offsets match hardware offsets exactly.
\end{DoxyEnumerate}

The {\ttfamily M\texorpdfstring{$<$}{<}PERIPH\texorpdfstring{$>$}{>}} macros then cast the base address to that struct, which is how every driver reaches the hardware, e.\+g. {\ttfamily MGPIOA-\/\texorpdfstring{$>$}{>}ODR \texorpdfstring{$\vert$}{|}= (1 \texorpdfstring{$<$}{<}\texorpdfstring{$<$}{<} 5);}.

\begin{DoxyWarning}{Warning}
Member order and the {\ttfamily RESERVED} padding arrays are load-\/bearing:\+ they are what makes each member land on its real hardware offset. Never reorder a member or drop a padding field. 
\end{DoxyWarning}
\begin{DoxyNote}{Note}
Register bit {\itshape positions} do not live here — each driver keeps its own bit definitions in its {\ttfamily \texorpdfstring{$<$}{<}NAME\texorpdfstring{$>$}{>}\+\_\+private.\+h}. 
\end{DoxyNote}
