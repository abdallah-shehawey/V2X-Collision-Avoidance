\doxysubsection{Detailed Description}
Newlib low-\/level stubs, plus {\ttfamily printf} retargeting over the ITM. 

\begin{DoxyAuthor}{Author}
Auto-\/generated by STM32\+Cube\+IDE 
\end{DoxyAuthor}
Newlib expects a hosted operating system underneath it. There isn\textquotesingle{}t one here, so every POSIX call it might reach for has to be answered by something. This file provides those answers.

Two kinds of function live here:\+


\begin{DoxyItemize}
\item {\bfseries{The one that does real work.}} \doxylink{syscalls_8c_aa025a12d45f60c7d0eae249e61f0c7f9}{\+\_\+write} is what {\ttfamily printf} ultimately calls, and it is retargeted onto the Cortex-\/\+M4\textquotesingle{}s ITM trace port via \doxylink{syscalls_8c_a044830d2e9de5ea57c8478e72a02ae9c}{ITM\+\_\+\+Send\+Char}. That is what makes {\ttfamily printf} show up in the debugger\textquotesingle{}s SWO console with no UART involved.
\item {\bfseries{Everything else.}} {\ttfamily \doxylink{syscalls_8c_a6cb6331c9d166180903d5fb78b9c9dd7}{\+\_\+fork}}, {\ttfamily \doxylink{syscalls_8c_ad2a07db8fdf26151eb98ba5711fad8c5}{\+\_\+execve}}, {\ttfamily \doxylink{syscalls_8c_a31da4cd5328defa76a9e2246992aba12}{\+\_\+link}}, {\ttfamily \doxylink{syscalls_8c_a70b2f211d665cded5637065aa2bb89dc}{\+\_\+unlink}} and friends are stubs that fail politely:\+ they set {\ttfamily errno} and return -\/1. They exist only so the linker resolves them; nothing in the firmware calls them.
\end{DoxyItemize}

\begin{DoxyNote}{Note}
The ITM is a Cortex-\/\+M3/\+\+M4/\+\+M7 feature. This file would not work on an M0/\+\+M0+, which has no ITM.
\end{DoxyNote}
