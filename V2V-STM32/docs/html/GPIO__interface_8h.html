Detailed Description

Public API of the GPIO driver: pin/port configuration and I/O.

Author
Abdallah Abdelmoemen Shehawey

The driver works at three granularities, all backed by the same registers:

  • single pin — GPIO_enumPinInit, GPIO_enumWritePinVal, GPIO_enumReadPinVal, GPIO_enumTogPinVal. This is what the LED, buzzer and ultrasonic drivers use.
  • a slice of a port — a nibble (4 pins), a byte (8 pins), a half-port or a whole port, configured in one call so a parallel bus does not need sixteen separate init calls.
  • raw port access — GPIO_enumReadPortVal and friends.

Every entry point validates its arguments and reports the outcome through ErrorState_t; none of them can fault on a bad port or pin index.

Note
The port's clock must already be enabled in RCC (RCC_enumAHB1EnableCLK) before any function here has an effect: a GPIO port with its clock gated off ignores writes and reads back as zero.
