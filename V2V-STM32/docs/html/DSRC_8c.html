Parsed-frame queue

A single-producer / single-consumer ring buffer sitting between the parser and DSRC_Update.

It is deliberately allowed to drop a frame when full rather than block or overwrite: losing one 100 ms broadcast is harmless, since the sender repeats it, whereas stalling the parser would back up the UART.

Detailed Description

Neighbor table, frame parser and transmitter for the V2V link.

Author
Abdallah Shehawey

Three pieces live here:

  1. a byte-at-a-time frame parser (DSRC_RxCallback), written as an explicit state machine so a garbled or half-received frame can never leave the parser stuck — it simply falls back to WAIT_START;
  2. a small queue of successfully parsed frames, which decouples parsing from the table update;
  3. the neighbor table itself, one row per vehicle heard from recently.

See Frame layout in DSRC.h for the frame layout.

XOR checksum over a byte range — the same one the ESP32 computes.

Parameters
[in]dataFirst byte to fold in.
lenNumber of bytes.
Returns
The XOR of all len bytes.
Note
An XOR is weak as error detection goes: it catches any single-bit error and any odd number of flipped bits, but two bits flipped in the same column cancel out. It is what the ESP32 side computes, so the two must match.

◆ update_neighbor()

void update_neighbor ( const Neighbor * msg)
static

Fold one received frame into the neighbor table.

A sender already in the table overwrites its own row; a new sender takes the next free slot. Once the table holds MAX_NEIGHBORS vehicles, further new senders are ignored.

Parameters
[in]msgThe frame to merge in.
Note
The row is stamped with the local FreeRTOS tick, not the sender's last_update. The sender's timestamp comes from its own clock, which has no fixed relationship to ours, so it cannot be compared against anything here — DSRC_RemoveStale would either purge everyone or no one.
