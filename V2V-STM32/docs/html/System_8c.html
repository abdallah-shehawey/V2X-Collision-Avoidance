◆ vESP_UART_RX_Callback()

void vESP_UART_RX_Callback ( void )
extern

USART1 receive ISR callback: push one byte onto G_xESP_RX_Queue.

Called from interrupt context for every byte the ESP32 sends. It does the minimum possible — read the byte, enqueue it — and leaves all DSRC framing and parsing to vTask_ESP_Comm, which can afford to block on a mutex.

The byte is read straight out of the USART data register rather than through the driver's blocking receive, because polling the busy flag here would deadlock against a transmission already in progress.

Warning
Runs in interrupt context, so it may only use the ...FromISR FreeRTOS API. That in turn requires USART1's NVIC priority to be numerically at or above configMAX_SYSCALL_INTERRUPT_PRIORITY (5) — see the warning on Task set.

◆ vApplicationStackOverflowHook()

void vApplicationStackOverflowHook ( TaskHandle_t xTask,
char * pcTaskName )

FreeRTOS stack-overflow hook: a task ran off the end of its stack.

Parameters
xTaskHandle of the offending task.
pcTaskNameIts name, which is the useful part when this fires under a debugger.
Note
Halts with interrupts disabled rather than trying to recover. There is no recovering: the task's stack has already overwritten whatever sat below it, so memory is corrupt and continuing would just hide the cause. Stopping here also stops the watchdog being kicked, so the MCU resets — which is the safe outcome in a vehicle.

◆ vApplicationMallocFailedHook()

void vApplicationMallocFailedHook ( void )

FreeRTOS malloc-failed hook: the heap could not satisfy an allocation.

Note
Halts, for the same reason as vApplicationStackOverflowHook. All allocation here happens at startup, so a failure means the heap was mis-sized — a build-time bug, not a runtime condition to ride out.
