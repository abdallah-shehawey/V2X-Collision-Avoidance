◆ MPU9250_enumInit()

ErrorState_t MPU9250_enumInit ( void )

Bring the IMU up: reset it, configure it, and enable its internal I2C master so the magnetometer becomes reachable.

Also verifies the WHO_AM_I identity register, so a mis-wired or dead part is reported here rather than showing up later as plausible-looking garbage.

Return values
OKThe IMU answered and is configured.
NOKThe identity check failed — check the SPI wiring and CS.
TIMEOUT_STATEThe part did not respond in time.

ErrorState_t MPU9250_enumReadData ( MPU9250_Data_t * Copy_pData)

Read the accelerometer, gyroscope, magnetometer and temperature in one burst.

Reading the whole block in a single transfer is what keeps the axes coherent — three separate reads could straddle two samples and describe a vehicle orientation that never existed.

◆ MPU9250_enumGetHeading()

ErrorState_t MPU9250_enumGetHeading ( MPU9250_Data_t * Copy_pData,
float Copy_fDt,
float * Copy_pfHeading )

Fused compass heading: the magnetometer, corrected for hard iron, blended with the integrated Z gyro through a wrap-aware complementary filter.

"Wrap-aware" matters: heading is circular, so 359° and 1° are two degrees apart, not 358. A filter that averages them naively swings the heading right through the back of the compass every time the car crosses north.

Parameters
[in]Copy_pDataA fresh reading from MPU9250_enumReadData.
Copy_fDtTime since the previous call [s]. Feeding it a wrong value scales the gyro term and corrupts the fusion.
[out]Copy_pfHeadingReceives the heading [degrees], 0..360.
Return values
OKThe heading was updated.
NULL_POINTERCopy_pData or Copy_pfHeading was NULL.
Note
The heading is only absolutely correct once MPU9250_enumCalibrateMag has run. Without it the value is still smooth and still tracks turns, but it is offset from true north by however much iron is in the car.
See also
MPU9250_HEADING_ALPHA, MPU9250_GYROZ_SIGN

◆ MPU9250_enumCalibrateMag()

ErrorState_t MPU9250_enumCalibrateMag ( void )

Boot-time hard-iron calibration: learn and freeze the magnetometer's X/Y bias.

Turn the vehicle through a full circle — one or two slow rotations — while this runs. It samples the field for MPU9250_MAGCAL_DURATION_MS and takes the centre of the circle the readings trace out as the offset.

Return values
OKThe car turned far enough; the offsets were computed and applied.
NOKThe field span was under MPU9250_MAG_MIN_SPAN, meaning the car did not really turn. The previous offsets are left untouched rather than replaced with a meaningless one.

◆ MPU9250_enumGetSpeed()

ErrorState_t MPU9250_enumGetSpeed ( MPU9250_Data_t * Copy_pData,
float Copy_fDt,
float * Copy_pfSpeed )

Estimate forward speed by integrating acceleration, with gravity removed.

Gravity compensation is not optional: a car on a 5° slope reads a persistent ~0.09 g along its axis, and integrating that unremoved invents about 0.9 m/s of speed every second the car sits still.

Parameters
[in]Copy_pDataA fresh reading from MPU9250_enumReadData.
Copy_fDtTime since the previous call [s].
[out]Copy_pfSpeedReceives the speed [cm/s], the unit the ADAS modules and the DSRC broadcast both expect.
Return values
OKThe speed was updated.
NULL_POINTERCopy_pData or Copy_pfSpeed was NULL.
Warning
This is dead reckoning from an accelerometer, so the estimate drifts: any residual bias is integrated without bound. It is good enough for the short-horizon time-to-collision maths, and it is not a substitute for a wheel encoder.

Advance the dead-reckoned position by one step.

Projects the current speed along the current heading and accumulates it, with pitch used to separate real forward motion from the gravity component.

Parameters
[in]Copy_pDataA fresh reading from MPU9250_enumReadData.
Copy_fSpeedCurrent speed [cm/s], from MPU9250_enumGetSpeed.
Copy_fHeadingCurrent heading [degrees], from MPU9250_enumGetHeading.
Copy_fPitchCurrent pitch [degrees], from MPU9250_enumGetAttitude.
Copy_fDtTime since the previous call [s].
[out]Copy_pPosReceives the updated position.
Return values
OKThe position was advanced.
NULL_POINTERCopy_pData or Copy_pPos was NULL.
Warning
Inherits the drift of MPU9250_enumGetSpeed and then integrates it a second time, so the position error grows quadratically. Treat it as a short-term relative estimate, never as an absolute location.

ErrorState_t MPU9250_enumGetAttitude ( MPU9250_Data_t * Copy_pData,
float Copy_fDt,
float * Copy_pfPitch,
float * Copy_pfRoll )

Pitch and roll, from a complementary filter over the accelerometer and gyro.

The accelerometer alone can find "down" but is corrupted by every bump; the gyro alone is smooth but drifts. Blending them gives an angle that is both steady and drift-free.

Parameters
[in]Copy_pDataA fresh reading from MPU9250_enumReadData.
Copy_fDtActual time since the previous call [s]. The caller passes the measured value rather than a nominal one, because a jittery period would otherwise mis-scale the gyro term.
[out]Copy_pfPitchReceives the pitch [degrees].
[out]Copy_pfRollReceives the roll [degrees].
Return values
OKPitch and roll were updated.
NULL_POINTERAny of the pointer arguments was NULL.
